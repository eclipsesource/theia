# Experimental Tauri example (Linux)

This example uses the same Theia extension dependency inventory as `examples/electron`. It is an experimental source integration with incomplete desktop parity. The Rust host starts a Node desktop controller, which owns one backend per workbench window. Each window has its own loopback port, security token and WebKit data directory. The controller provides a narrow bridge for window controls and native file dialogs. Tauri JavaScript invoke capabilities remain disabled.

## Prerequisites

- Node.js 24 or newer, npm, Rust and Cargo.
- A Linux graphical session and the Tauri 2 Linux development libraries: WebKitGTK 4.1, JavaScriptCoreGTK 4.1, libsoup 3, GTK 3, and their dependencies. On Ubuntu, see the [Tauri Linux prerequisites](https://v2.tauri.app/start/prerequisites/#linux).
- `xdg-open` for the navigator's system editor and containing-folder commands.
- The repository's normal native Node dependencies installed for the selected Node executable.

From the repository root, run `npm install`, `npm run compile`, then `npm run build:tauri`. Start it with `npm run start:tauri -- --port=3000 /path/to/workspace`. `build:tauri` compiles the Rust host explicitly; normal builds of other targets do not require Rust. The generated frontend and backend bundles are local to `examples/tauri/lib`.

Use a disposable profile while evaluating: set `THEIA_CONFIG_DIR`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, and `XDG_CACHE_HOME` to separate directories. The primary WebKit data directory is created under `THEIA_CONFIG_DIR/tauri-webview` when `THEIA_CONFIG_DIR` is set; other windows use subdirectories there. An explicit free port is required for reproducible first-window runs; ports 1–65534 are accepted. The port is not reserved and a collision fails startup. New windows use temporary free ports and retry if another process claims a selected port before the backend binds it. A second launch with the same application and profile forwards its workspace path and CLI arguments to the running controller and then exits. `Alt+Shift+N` opens an empty workbench window.

`npm run watch:tauri` watches TypeScript and application bundles. Rust edits require `npm --prefix examples/tauri run build:host` and restarting the application. Rebuilds that switch between Electron and standalone Node native modules must be run serially with the other target stopped.

The build also emits a separate `lib/backend/remote-main.js` entrypoint. It requires a per-session `THEIA_TAURI_REMOTE_TOKEN` and serves authenticated HTTP and WebSocket requests without native-window bindings. The local backend has a session-scoped `/tauri-remote/<session-id>/services` WebSocket gateway that requires the window's existing cookie and Origin before forwarding to a remote backend with its separate token. Its `/tauri-remote/<session-id>/files` and `/tauri-remote/<session-id>/file-upload` routes stream remote file transfers through the same authenticated local origin. Tauri remote setup selects `remote-main.js`, binds it to remote loopback, and passes a fresh token in the process environment. SSH and dev-container providers register and dispose gateway sessions with their connections. The frontend selects that remote service channel using a `remoteSession` query parameter on the window's existing origin, while native and setup services stay local. A Tauri remote install uses its own `-tauri` directory suffix so it does not overwrite an Electron remote install.

To try a container, start the example, then run **Dev Container: Attach to Running Container** from the command palette. Select a trusted running Linux container with `tar` and `xz` installed, then choose its workspace path. The workbench reloads in the current window. **Close Remote Connection** returns to the local workbench. The disposable `debian:trixie-slim` UI check needed `xz-utils` installed first. In later runs, the window edited an unmounted `/workspace/hello.txt`, ran a workspace task inside the container, reconnected, and activated a remote extension. Its webview script, service worker and plugin file fetch succeeded; an attempted privileged WebSocket was denied. Tauri serves the panel's frame from the owning local window endpoint. The attached container itself stays running because the attach workflow uses `shutdownAction: none`; its remote backend uses an idle shutdown timer. A separate native check built a Dockerfile from `devcontainer.json`, created the container, edited its workspace and ran a terminal there. Other devcontainer configurations, remote HTTP resources and extended sessions still need full UI checks.

After bundling, run the `test:remote-backend-auth`, `test:remote-gateway`, `test:remote-setup`, `test:remote-ssh-provider`, `test:remote-service-path`, `test:remote-container-provider`, `test:remote-container-tunnel`, and `test:remote-port-forwarding` scripts in this example. `test:remote-container-integration` additionally requires Docker with the `debian:trixie-slim` image, a Linux Node 24 executable, and the example bundle. It bind mounts the checkout and uses a disposable container to exercise the gateway and a forwarded TCP port through real Docker exec tunnels, including cleanup. The Ports view forwards a numeric remote port to the same port on local loopback during a Tauri remote session. A native UI check reached an HTTP service inside the container through that port, then confirmed the port closed with the remote connection. Another native UI check connected to a disposable OpenSSH server, ran a terminal in the SSH backend, opened a remote folder through Theia's file picker, and saved an edited file in that workspace. The same SSH session saved an untitled editor to a new remote file through Theia's Save As dialog at 1280×800. **SSH: Connect to Host...** opens a new window that owns its remote backend; **SSH: Connect Current Window to Host...** reloads the current window. A new-window UI check opened a remote terminal and saved an edited SSH file while the source window remained local. The Ports view also forwarded an HTTP service through an isolated Docker SSH target and closed the listener on disconnect. Other remote HTTP resources still need work.

A native container session prepared and fetched a remote file through the session-scoped download route. The same window uploaded a new file through the workbench upload service, and the bytes were verified inside the container. A later check selected a host file through GTK **Select Files** from the navigator’s **Upload Files...** action and verified its bytes in the remote workspace. Save As also prompted before overwriting an existing remote file: Cancel kept the original bytes, and OK wrote the editor text. The gateway test covers transfer methods, local authentication, cross-origin denial and cleanup. Remote editor decoration files and extension icon assets use the same session-scoped origin through `/file` and `/hostedPlugin`; installed-extension assets in the Extensions view and webview tab icons also use that route. A native container check fetched an extension icon and a decoration file from remote-only paths, then received 404 for each after disconnect. A later native check rendered a remote extension's SVG icon in the Extensions view and, with a file icon theme enabled, on its webview tab, a remote workspace file and an editor gutter decoration. A connected native container session stayed ready beyond the five-minute remote idle window and read a remote file successfully before disconnect and reconnect. A later native window completed three short attach cycles against one container. An unsaved untitled editor prompted on disconnect: Cancel kept the remote editor and text, while Don’t Save returned to the local workbench. Other remote HTTP resource paths remain open.

The Electron example was run separately under Xvfb with its own profile and a disposable Debian container exposing the same unmounted `/workspace` path used for the Tauri checks. It attached, opened and saved `/workspace/parity.txt` through the editor, ran `pwd` in an integrated terminal inside the container, disconnected to its local workbench, and attached again. The file bytes and terminal output were checked inside the container. This is a focused remote workspace reference for both targets; it does not cover the full Electron workflow matrix.

The gateway check also transfers 8 MiB in each direction, verifies that cancelling a download closes its upstream response, and checks that an unreachable remote service fails and removes its session. The Docker integration check transfers 8 MiB through the real remote backend and Docker exec tunnel in both directions and verifies the uploaded file hash inside the container. A native container session then uploaded an 8 MiB host file through GTK **Select Files** and downloaded it through the navigator, with matching SHA-256 on both sides. WebKitGTK originally saved the download in the workbench's current directory. The native host now directs downloads to the user's Downloads directory, keeping existing files by adding a numeric suffix. A local native check saved the same filename twice as separate files, and a remote container check saved an 8 MiB file in a disposable XDG Downloads directory with its source hash intact. Rust tests verify that reservations are released after failed downloads, including overlapping requests for the same URL and rejected requests. Long native sessions and cancellation under UI load still need coverage.

For a real SCM and Node debugging check, a disposable profile loaded the Open VSX `vscode.git-base` and `vscode.git` extensions at 1.95.3 plus `ms-vscode.js-debug` at 1.140.0 through `--plugins=local-dir:<directory>`. In a disposable Git workspace, Source Control showed an untracked file, opened its diff and staged it. A `.theia/launch.json` entry with `type: "node"` paused at a `debugger` statement, showed the call stack and locals, and resumed. The same plugins and workspace passed those checks in Electron. The adapter selected Node 22 from this machine's runtime environment in both targets; set `runtimeExecutable` in the launch entry when the program requires Node 24.

A disposable local workspace task printed a synthetic compiler error, parsed it with a configured problem matcher, and displayed one Problems entry. Opening the entry focused the source file at line 2, column 3. A separate two-run fixture produced one error on its first run and clean output on **Rerun Last Task**; the Problems entry cleared in both Tauri and Electron after the rerun path was fixed. A background watcher also reported one error in its first cycle and cleared it at the next cycle's begin pattern in both hosts. Remote task diagnostics remain untested.

Dragging a local file from the Explorer root onto a child directory moved it on disk in both Tauri and Electron, with matching contents. An external Nautilus file dropped into blank space in Tauri's local Explorer now copies into the workspace root and opens, matching the checked Electron outcome. In a multi-root workspace, blank space targets the last root, as in Theia's existing tree drop behavior. A two-file Nautilus drop also copied both files with matching hashes. A folder with one child file copied and opened that child in both Tauri and Electron. The native bridge accepts regular files and directories, rejects symlinks and special files, expires each drop after 30 seconds, and never overwrites an existing name. A drop over the editor did not copy. Drops onto a specific Explorer row did not consistently produce a native event under Xvfb; copy modifiers, other file managers and Wayland remain untested. For remote workspaces, use Explorer’s **Upload Files...** action; its native GTK picker and upload path have passed local and remote checks.

If an active remote backend exits unexpectedly, the gateway discards its session and the workbench returns to its local backend after a failed reconnect. Native SSH and dev-container checks killed `remote-main.js` while connected; each window returned to local `ready`, and later connections to the same target worked. An unsaved editor may veto the return so its contents can be recovered.

The small VS Code plugin at `packages/tauri/test-plugins/webview-probe` can be copied into a disposable profile's `plugins` directory. It activates at startup and exposes `Tauri Probe: Open Webview` to check webview script, local resource, HTML update, dispose/recreate, reload and relaunch restoration, service worker readiness, and service-channel isolation. Accept workspace trust in the disposable profile before testing plugin activation.

`Tauri Probe: Open View` focuses the probe's webview view in Explorer. Its log reports `view-ready`, `view-resource`, and `view-authority` results for script execution, a local extension resource, and denial of the trusted service WebSocket.

The same probe exposes `Tauri Probe: Test Secret Storage` for a store/read/delete check and `Tauri Probe: Store Secret For Relaunch` for a same-profile persistence check. The latter reports its result in the plugin log on next activation and deletes the fixed test value.

`Tauri Probe: Open Custom Editor` creates a disposable file in the plugin's global storage and opens it with a custom text editor. The editor checks script execution, a local webview resource, service-worker readiness and denial of the trusted service WebSocket. Under Xvfb, all four results appeared in the plugin log; the custom editor also rendered in the workbench.

`Tauri Probe: Test Save Dialog` opens the native save picker with a `.txt` default name and writes the selected file in the plugin's global storage. Accepting the default selection returned and wrote `new-save.txt` under Xvfb.

For plugin development, run **Hosted Plugin: Select Path** and choose a local extension directory, then use **Start Instance**, **Restart Instance**, **Debug Instance**, and **Stop Instance**. The hosted extension runs in a separate native window with its own backend and profile. The debug command starts a Node inspector on loopback; an external Inspector Protocol client attached, evaluated, paused, and resumed the plugin host. The workbench still reports that debug session type `node` is unsupported because this example has no Node debug adapter. An in-workbench breakpoint session requires a compatible adapter. Closing the parent window stops its hosted child.

The `native-module-probe` and `headless-probe` under `packages/tauri/test-plugins` exercise native addon loading and Theia headless-plugin start/stop respectively. A disposable copy of `native-module-probe` also loaded its own `node-pty` and `native-keymap` binaries from the extension's `node_modules`. A local VSIX built from `webview-probe` installed through **Extensions: Install from VSIX...**, activated without reload, and reactivated after a same-profile relaunch. Uninstalling it from the Extensions view removed the deployed directory; it stayed absent after relaunch. In a separate disposable profile with the example's Open VSX router configuration, the Extensions view installed `vscode.git` 1.95.3 and its `vscode.git-base` dependency. Source Control detected an untracked file, including after a clean same-profile relaunch. Uninstalling Git removed its deployed package; after window reload the install action returned and the Source Control badge cleared. The dependency remained installed separately. A second native profile used **Install Specific Version...** to install Git and Git Base 1.88.1, then selected Git 1.95.3. Both packages changed to 1.95.3; after window reload the version picker marked 1.95.3 current and Source Control detected a test repository. These checks used disposable profiles under Xvfb; automatic update detection and extensions requiring an external service remain untested.

The `notebook-probe` fixture can be deployed from `packages/tauri/test-plugins/notebook-probe`. Run **Tauri Probe: Open Notebook**, select **Tauri Probe Kernel**, then **Run All**. Its output should read `TAURI_RENDERER_2_PRELOAD_OK_KERNEL_OK_OUTSIDE_BLOCKED`: the custom renderer loaded, its static and kernel preloads ran, and a request outside the extension directory was denied. Switch to **Tauri Probe Alternate Kernel** and run again; the output should contain `RENDERER_3` and `KERNEL_ALT_OK`. Switching back restores the first result. The `scm-probe` fixture registers a source control provider when a workspace is open. Run **Tauri Probe: Populate SCM**, open Source Control, then double-click `tauri-scm-probe.txt` under Changes. The extension log reports provider registration, one resource state, and the file-open command. This checks the VS Code SCM API path; the real Git checks above cover one local repository workflow separately.

## Current limitations

The example uses a Tauri-specific raw WebSocket service channel because the WebKitGTK Socket.IO path stalled during startup in repeated Xvfb runs. A native close request asks the frontend whether it may shut down; this has been checked under Xvfb with a window manager. The `close.window` command used the same close path and shut down a disposable host cleanly. Native open, folder, and save dialogs work for local files, while remote and mixed file/folder selection use Theia's dialog. The navigator's system editor and containing-folder commands send local file URIs to an `xdg-open` backend service; remote URIs are refused. The external-terminal adapter also rejects remote workspace URIs; a configured executable was verified to start in a local workspace directory. The active editor title updates the native window title. Frontend commands for focus, minimize, maximize, fullscreen and zoom use the native bridge. Zoom preference changes and reload persistence were checked in WebKitGTK. On the available X11 display, maximize, fullscreen and minimize changed the expected window-manager states. An X11 activation request restored a minimized window after Tauri's unminimize/show/focus calls; Wayland focus behavior remains untested.

In a native Xvfb window, File showed **Auto Save** checked and **Save As...** disabled with no file editor. Clicking **Auto Save** removed the check; clicking it again restored the check. Opening a local text file enabled **Save As...**, and selecting it opened GTK's native save dialog. This covers one checked transition, one enabled transition and one menu action; other menu state changes and layout-sensitive shortcuts remain untested. A separate Xvfb check switched the OS layout from US to German and observed the backend keymap and frontend layout-change callback.

AT-SPI exposed the native menu and the WebKit workbench tree under Xvfb. The editor appeared as an editable, multiline **Editor content** entry with the saved text and caret offset, while File menu items reported checked and enabled states. The same tree appeared after a normal relaunch without an explicit GTK accessibility module setting. This is an accessibility API check; screen-reader navigation and speech, keyboard-only workflows, and other widgets remain untested.

An isolated IBus session with the Wubi table engine also reached the native editor. Typing `a` displayed a composition candidate for `工`; Space committed it. Escape canceled a later preedit without changing the file, and `b` plus Space committed `了`. The saved file contained `工了IME proof`. This checks one real GTK input method and composition path under Xvfb; other input engines, layout and shortcut combinations, and an Electron reference remain untested.

In a disposable local workspace, opening and saving `link-alias.txt` changed the target file while preserving the symbolic link. A `0444` file inside a `0555` directory opened with a lock icon and rejected typing with **Cannot edit in read-only editor**; its original bytes stayed intact. With autosave off, changing a dirty file and its directory to those permissions made Save fail in both Tauri and Electron while preserving the unsaved text and original disk bytes. The shared Save command now shows the `EACCES` error in both hosts; restoring permissions lets the queued editor save succeed without losing the unsaved text. Opening a mode `000` file showed an error and left the editor closed in both targets. Remote permission paths and symlink escape behavior need separate checks.

The Tauri clipboard service uses the native bridge for text because WebKitGTK's browser Clipboard API rejected read and write in this host. Unicode text copied from Theia was readable by `xclip`, and Theia read text owned by `xclip` in Xvfb. Rich clipboard formats and persistence after the owner exits are untested.

Extension webviews use `*.webview.localhost` on a separate `::1` content server at the same port as the trusted `127.0.0.1` backend. The source-built probe loaded its script and local resource, received messages after an HTML update and dispose/recreate, and could not open the trusted service WebSocket. Its serializer restored the panel after frontend reload and after same-profile relaunch; resource loading and WebSocket denial still held. Its service worker reported ready. The server also serves local mini-browser previews on random, temporary `*.mini-browser.localhost` hosts. Each host is limited to the previewed file's directory; traversal, symlink escapes and unknown hosts are denied. A local HTML preview and its relative CSS rendered under Xvfb. The embedded page could not open trusted HTTP or WebSocket services or navigate the top-level window; a request using valid workbench cookies but a mini-browser Origin was denied. The probe's custom text editor opened and reported script, resource, service-worker and WebSocket results. The notebook probe rendered an extension-supplied output module and preload through the scoped webview resource service. The full authority boundary remains unverified.

The remote mini-browser keeps the iframe on the same isolated local host. Its preview grant is registered with the active remote backend, which checks the real file directory before serving each requested path. A native container preview rendered remote HTML and relative CSS; symlink escape, encoded traversal, an ungranted host and access after disconnect returned 403. The remote preview route is available only through the backend session token.


An earlier repeated-launch stall was traced to `@parcel/watcher` hanging when this desktop session exhausted its Linux inotify instance limit. Tauri uses snapshot polling for the two small AI registry watches; three subsequent launches of one profile with the probe plugin reached `ready`. Killing each of the host, controller and backend after readiness closed the remaining process tree and backend port in disposable tests. Closing through `close.window` with a live terminal running `sleep 300` stopped the shell child; killing the native host with an active `sleep 300` terminal also stopped that process and closed the backend port. The host and controller failure checks were repeated with a hosted development window; owned backends and plugin hosts exited. This does not establish long-session reliability or cleanup after every crash. Two independent workspace windows, a forwarded second launch, and closing one window while the other remains open were checked under Xvfb. Forwarded launches create a separate backend using their CLI arguments. Main-process contributions can claim a launch to open an empty window for a startup workflow. A close request during frontend startup now reaches the backend close coordinator. Reopening every prior window, complete remote and dev-container parity, other native services, and the broader Electron workflow matrix remain incomplete. Do not use this target with untrusted workspaces or extensions.

Normal native close now runs Theia's unload hook after the frontend accepts the close, so the current editor layout is stored before Tauri destroys the webview. A local editor's saved text and open tab restored after closing and relaunching the same disposable profile. A separate cold launch with no workspace argument restored the prior local workspace and editor, matching Electron's one-workspace cold-launch behavior. Abrupt exits, remote sessions and other session state have not been covered by that check.
